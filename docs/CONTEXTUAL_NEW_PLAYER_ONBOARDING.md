# Contextual new-player onboarding

This client presentation update provides optional guidance for editing the ruler name and kingdom flag, then the first city upgrade, scout, and city attack. It uses the current monthly realm and existing runtime configuration without altering world data, gameplay authority, costs, balance, or permissions. Camp attacks and capture are excluded from beginner guidance at the user's direction: new rulers do not have the troops for these objectives. Normal Camp information and gameplay remain available.

## Player experience

- A newly confirmed starting-city claim enables the tips before any starting-map redirect. Replayed claims preserve an existing dismissal. Existing players can enable or replay tips through **Profile → Settings → First steps & help**.
- A compact map card starts with the Profile portrait and the name and flag topics. Profile guidance points to the pencil, name field, and save check mark, then Edit flag, customization choices, and Save Flag. The copy explains the existing 18-character name limit and explicit flag saving. Existing save, retry, and unsaved-draft protection remain unchanged. **Got it** moves past each topic when the ruler is ready.
- City guidance follows the selected city. The corresponding city Info, scout report, or attack confirmation explains the action alongside its existing controls. Camp and Stronghold selections do not offer beginner map guidance; Camp Info, scouting reports, and attack dialogs omit beginner tips.
- Upgrades show the current projected next-level cost and explain production. Low Gold and incoming-attack conditions use existing checks. Scouting explains the one-troop march, waiting for arrival, Reports, the configured intelligence lifetime, and the limits of a snapshot. Attacks explain choosing troops, reviewing the forecast and travel time, confirming, and reading the arrival result.
- Gold arrows use the actual control bounds, including the selected city's own action wheel and the +1 and troop-slider controls in dialogs. They follow camera movement, panel changes, scrolling, resizing, and settled transitions. Obscured, offscreen, disabled, and pending actions do not receive arrows. A report-ready tip points to Reports; the report itself points to its Close control. Arrows never intercept input, steal focus, or submit actions. A single SVG moves into the dialog's top layer when needed; updates are event-driven and coalesced into one pending animation frame, with no continuous animation loop.
- **Got it** dismisses the topic; it is an acknowledgement of guidance, not a gameplay completion claim. **Hide tips** turns off all tips. Neither submits a gameplay action, pauses the realm, nor changes eligibility. Dismissals are local UI preferences keyed by account, world, reset generation, and shard. They survive reloads where browser storage is available; unavailable storage falls back to the current session. Other open tabs receive storage preference updates. Adding name and flag topics preserves existing opt-outs and city-topic dismissals; obsolete Camp dismissals are ignored.
- The existing parchment palette and font are preserved. Map guidance sits clear of the bottom navigation and hides behind dialogs, Profile, setup, and transient toasts. Dialogs retain their existing scrolling and action controls. Stable HUD updates retain the guide DOM and keyboard focus.

Settings provides a short five-topic Help overview and a button to replay the guidance.

## Validation and release

`tools/validate-onboarding-guidance.js` covers first-claim opt-in, dismissal and replay, reload, account/realm isolation, signed-out behavior, restricted browser storage, existing opt-outs, current costs/report lifetime, identity copy, and Camp exclusion. `tools/validate-onboarding-browser.js` exercises actual panels against isolated local services at desktop 1440×900 and landscape 844×390: all five topics, arrow geometry and click-through behavior, stable DOM/focus, pending/disabled scouting, upgrade controls, attack sliders, scrolling, camera movement, Camp exclusion despite ownership changes, dismissal, and replay through Settings. Controlled flag-save failures and retries preserve the draft and existing confirmation path. The check records uncaught errors, horizontal overflow, and settled 44-pixel dismissal targets in `release-artifacts/onboarding-controls/`.

Both checks are part of the static release gate. The complete repository gate, production build, required GitHub checks, and combined diff review must pass before merge. This is a client-only release: no Functions source, Firestore rules, indexes, world migration, cleanup job, or production-data change is required. Netlify publishes the merged web commit through the established Git deployment. Release-channel proof belongs in the release handoff; these implementation requirements alone do not establish live status.

Help reuses the contextual copy instead of duplicating it. Identity guidance and arrows add less than 8 KiB to the existing installation shell. The bounded installation-cache allowance advances from 3,648 to 3,656 KiB; the runtime and stylesheet allowances advance by 8 and 2 KiB respectively. No artwork, dependency, or additional runtime request is introduced.

Physical phone testing remains excluded at the user's request. Browser tests use isolated fixtures; production smoke tests remain signed out and do not consume real-player resources. Preferences do not synchronize across different browsers or devices.
